# 架构概览

SerialSpark 分为串口访问、会话协调、记录存储、协议解析和命令行编排几层。核心库由 `serialspark_core` 提供，CLI 将参数整理为配置和会话选项，再调用核心逻辑。

- `core`：字节/十六进制转换、JSON 读写、系统时钟和原始事件结构。事件包含序号、墙上与单调时钟、方向、字节和细节对象。
- `serial` 与 `baud`：Linux 串口发现、权限及可见占用检查、设备打开、串口参数设置和驱动回读验证。设备配置包含端口、波特率、数据位、校验位、停止位和流控。
- `session`：统一驱动 `send`、`session`、`capture`。它协调连接、输入源、部分写入、读取、超时、交互指令、事件输出和可选协议解析。TX 记录表示应用提交且驱动接受的字节，不代表设备确认。
- `record`：通过 SQLite/WAL 异步保存原始事件和元数据，按大小轮转分段并维护可校验的分段关系。队列有界；记录错误会停止采集并报告最后持久化位置。关闭时检查点并完成 WAL 收尾。
- `protocol`：纯声明式解析器。TX、RX 独立维护组帧状态；完成帧、噪声及残留都能关联回原始事件范围。实时解析与离线重解析共用同一解析引擎。
- `commands` 与 `main`：CLI11 命令树、参数校验、配置文件与命名配置管理、离线记录遍历/筛选/导出，以及退出码映射。

实时数据路径大致为：串口字节 → 原始事件 → 可选 SQLite 记录和可选协议解析 → human/JSONL 输出。离线路径从 `.ssr` 顺序读取原始事件，按新的协议配置重建帧，再执行方向、时间、内容和字段筛选；此过程不改写记录。

记录元数据包含请求配置、协议配置和设备发现信息。采集时间为应用观察时间。WAL 工作期间不要只复制主 `.ssr` 文件；干净关闭后记录器会检查点并关闭数据库，轮转分段各自保存完整性元数据。
